## 故障注入

- 端口占用：第二实例明确拒绝启动，主实例保持正常。
- DNS 失败：无效域名请求失败后，下一次有效请求立即成功，服务保持 active。
- Cloudflare 不可用：VLESS 明确标记失败，公开状态返回 `ok=false`、内置健康命令退出码为 1，AnyTLS/TUIC 和管理服务继续运行；组件恢复后隧道自动重建，健康命令恢复退出码 0。
- 配置不可写：订阅更新返回 HTTP 500，现有服务和配置不损坏。
- 证书缺失：首次启动自动生成新证书/私钥并设为 `0600`。
- 退出信号：SIGTERM 触发正常关闭，systemd 记录 clean deactivation。

## 已修复问题

1. cloudflared 输出管道提前关闭会导致子进程退出：现仅持续读取实际日志所在的 stderr，stdout 直接丢弃以避免无人读取造成背压；子进程启用 drop 强制终止，监听任务和隧道停止等待均有 5 秒硬超时，隧道 30 秒未就绪会明确进入失败状态并写入脱敏事件。
2. Quick Tunnel 订阅误用本地端口：现固定使用 Cloudflare 边缘端口 443，并有回归测试。
3. TUIC 默认流上限导致并发失败：扩大 QUIC 流/窗口上限并加入背压，128 流回归通过。
4. AnyTLS/TUIC 半关闭会丢失响应：现分别关闭写半部并等待反向数据完成。
5. VLESS 转发缺少握手/连接/中继超时：现增加边界并在上游连接成功后才返回成功响应。
6. 默认管理口令、明文密码、永久令牌和敏感日志：改为随机初始化、Argon2id、可过期会话和脱敏日志。
7. 配置保存风险：改为临时文件、同步和原子替换；节点变更在切换前预启动验证候选监听——同生产套接字的修改使用临时端口验证协议/TLS，新增或换端口直接验证目标端口。只有候选验证和正式监听全部成功后才持久化；目标端口冲突测试确认旧配置、旧监听及其任务 ID 均保持不变。
8. Clash 订阅中 AnyTLS `alpn` 列表缩进错误：经 Mihomo 实测发现并修复，新增回归断言；固定版本 Mihomo 已成功加载修复后的完整配置。
9. 管理页敏感信息默认裸显且底部面板没有真实日志数据：订阅地址、订阅正文、UUID 和节点密码现默认遮罩并支持显式查看；新增最多 200 条的脱敏管理事件缓冲区，过滤框同时筛选状态与事件，节点启动失败会醒目标红。公网运行版本已验证事件不包含会话或管理密码。
10. 运维文档原先只有外部 `curl` 示例，没有真正的健康检查命令：新增 `veloxvpn health --url ...`，连接、发送和读取均有 3 秒超时；公网实测健康状态退出码为 0、不可达端口退出码为 1。
11. 旧版配置中的已知默认管理员口令原本只会被哈希而不会轮换：现识别旧默认值和空密码，生成新的随机引导密码并写入 owner-only 文件；自定义旧明文密码只迁移为 Argon2id，避免无故锁定现有管理员。两条迁移路径均有真实旧格式 JSON 回归测试。
12. 管理账户修改、订阅重生成和 Quick Tunnel 公网地址更新在写盘失败时原本可能提前改变运行态：现先保存完整候选配置，成功后再替换内存状态；失败时保持旧配置并明确标记隧道错误。强制原子写盘失败的端到端测试确认账户、密码、订阅路径和令牌均保持原值。
13. 随机端口的可用性检查与真实监听之间存在竞争窗口：首次配置生成会对新端口重新检查并重试，启动监听遇到真实地址占用时会重新分配、成功绑定后再持久化；真实抢占端口的端到端测试验证了新端口与磁盘配置一致。
14. Unix SIGTERM 处理器安装失败原本会触发进程 panic：现记录明确错误并退回 Ctrl+C 信号等待路径；生产代码已无 `unwrap`、`expect`、`panic!`、`todo!` 或 `unimplemented!`，这些调用只存在于测试模块。
15. 公开健康状态原本只检查本地监听，Quick Tunnel 尚未就绪或已经失败时仍可能误报健康：现普通节点必须处于 `listening`，Cloudflare 节点还必须处于 `tunnel=ready`；启动中、未配置和隧道失败均返回 `ok=false`，并有状态映射回归测试。

## 已知诊断限制

从同一公网机经其 Quick Tunnel 回连自身/回环基准目标时，Cloudflare 返回 530 或出现约 3%–7% 失败；Windows 外部客户端访问普通公网目标在 20/50 并发下均为 100/100。该现象被归类为源站自回环/Cloudflare 边缘路径限制，不作为普通公网客户端转发失败，但 VLESS 的 24 小时判定由 Windows 外部探针单独完成。
